Section 4

Database & ORM

The application uses PostgreSQL hosted on Supabase with the Supavisor connection pooler (port 6543, transaction mode). Driver: asyncpg.

⚠️ Supavisor & Prepared Statements: Because Supavisor reuses physical connections across logical sessions, prepared statement names must be globally unique. The app uses prepared_statement_name_func = lambda: f"__asyncpg_{uuid.uuid4().hex}__" and disables asyncpg's statement cache (statement_cache_size=0) to prevent DuplicatePreparedStatementError.

ORM Pattern

  • SQLAlchemy 2.0 with async_sessionmaker and AsyncSession
  • Sessions use expire_on_commit=False, autoflush=False
  • Sessions injected via FastAPI dependency get_db()
  • Alembic manages all schema migrations — applied at each deploy
  • All primary keys: UUID v4 (Python-generated)
  • Timestamps: DateTime(timezone=True) with func.now() server defaults
  • Soft deletes via is_deleted / deleted_at / deleted_by on User model

Section 5

Middleware Stack

Starlette processes middleware LIFO (last-added = outermost). Order below shows request-processing order (outermost → innermost):

1
CORSMiddleware
Handles preflight OPTIONS before any auth checks. Allows: localhost:3000/3001, Vercel deployments. Credentials allowed, all methods/headers.
2
UnhandledErrorMiddleware
Catches unhandled exceptions and converts to structured JSON — ensures CORS headers preserved even on uncaught DB errors.
3
RateLimiterMiddleware
Fixed-window in-memory limiter by (path, IP). Limits: login 5/min, register 3/min, refresh 10/min. Returns HTTP 429.
4
SecurityHeadersMiddleware
Injects X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy, Permissions-Policy, CSP. Docs paths get relaxed CSP.
5
AuditMiddleware
Parses User-Agent once per request; caches IP/device/browser/OS on request.state.client_context for service-layer audit logging.
6
SessionMiddleware
Resolves request.state.session_id from authenticated user's active session for session-scoped operations.
7
ActivityMiddleware
Updates last_seen timestamp and session last_activity on authenticated requests for inactivity tracking.
8
AuthenticationMiddleware
Decodes Bearer JWT → sets request.state.user_id. Never rejects — route-level get_current_user dependency enforces protection.

Section 8

Security Model

🔑
JWT Authentication (Bearer Token)
Access tokens (30 min TTL) signed HS256 HMAC. Refresh tokens (7 days TTL) stored as hashes. Token type claim validated (access vs refresh). Protected routes use get_current_user dependency.
🔒
Password Security
bcrypt at 12 rounds. Password strength validation on register/change. Constant-time comparison via passlib to prevent timing attacks.
🚫
Account Lockout
After 5 consecutive failures → locked 15 minutes. State in users.locked_until. Reset on successful login.
⏱️
Rate Limiting
Fixed-window in-memory by (path, IP). Login: 5/min, Register: 3/min, Refresh: 10/min. Returns HTTP 429 with structured error.
📋
Audit Logging
All auth events → audit_logs table. Fields: action, user_id, IP, device info, old/new data (JSONB), timestamp. Events: register, login_success, login_failed, logout, refresh, access_denied, invalid_token, verification_*, password_reset_*, session_*, new_device_login.
🌐
CORS
Specific origins only: localhost:3000/3001, amplivo-front-and-backend.vercel.app, amplivo-2.vercel.app. Credentials allowed.
🔏
Security Headers (Every Response)
X-Frame-Options: DENY · X-Content-Type-Options: nosniff · Referrer-Policy: strict-origin-when-cross-origin · Permissions-Policy: geolocation=(), microphone=(), camera=() · CSP: default-src 'self'; frame-ancestors 'none'
🏢
RBAC + Tenant Isolation
Routes protected with require_roles("role_slug"). Client portal users scoped to their company via users.client_id — enforced by get_current_client_id dependency on all relevant endpoints.
📱
Device & Session Tracking
Each login creates session record: device, browser, OS, IP, country, city. Multi-device management: view, terminate individual or all other sessions. Session inactivity timeout (60 min).

Health & Monitoring

Health Check Endpoints

MethodPathUse CaseResponse
GET /health Liveness probe — never touches DB {"status":"ok"} HTTP 200
GET /health/database Readiness probe — executes SELECT 1 {"status":"healthy","database":"connected","latency":"2.5 ms"} 200 or 503
📌 Probe Strategy: Use /health as the liveness probe (container restart decisions) and /health/database as the readiness probe (traffic routing). This prevents unnecessary restarts when DB is temporarily unreachable during deployment.

Startup & Shutdown Behavior

  • Startup: DB connectivity check bounded to DB_STARTUP_TIMEOUT_SECONDS — app still boots even if DB unreachable
  • Startup failure: logs warning, continues boot — /health returns ok, /health/database returns 503
  • Shutdown: engine.dispose() called via lifespan context — graceful connection pool cleanup
  • Static files: /uploads served from Backend/uploads/ via Starlette StaticFiles
